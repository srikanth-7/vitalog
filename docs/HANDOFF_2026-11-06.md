## 2. Changes made today

### 2.1 Security review fixes (PENDING #27) ✅ code / 🔒 open items
- **Sealed box must match its row** — `report_sync_service.dart` `openBox`:
  a report box is refused unless its `report.profile_id` equals the row's
  `profile_id` and every result inside has `report_id == row.id` and the
  same `profile_id`. Stops a co-sharer (who holds the profile key) from
  planting results under another profile/report.
  Test: `test/privacy/sealed_sync_test.dart` (three planted variants).
- **`supabase/schema.sql`**
  - `drop_orphan_profile`: when someone loses access, their invite is
    marked `used_at = '-infinity'`, closing `may_take_profile`'s 10-minute
    re-entry window.
  - `open_invite`: per-invite lockout (`failed_attempts < 5`) removed — the
    token is 256-bit, and the lockout let anyone who saw the link id (host
    logs) burn the invite. `failed_attempts` is still counted. Per-account
    limit (10/hour) stays; old `invite_failures` rows (>1 h) are trimmed.
  - ⚠ **Re-run `schema.sql` on staging** (safe to re-run) to pick these up.
- **`supabase/cleanup_test_data.sql`** updated for global/shared ids
  (counts via `profile_keys`; deleting `profile_keys` drops sealed rows only
  when nobody else has access).
- **Recovery key Copy clears the clipboard after 60 s** —
  `recovery_key_sheets.dart` `copySecret()`; snackbar string
  `recoveryKeyCopiedClears` (replaces `recoveryKeyCopied`). `ponytail:`
  note: may wipe something copied since; iOS `UIPasteboard.expirationDate`
  via a channel if that matters.
- **Leftover scanner copies swept** — `HealthBloc.sweepScanCopies` deletes
  `scan-*.pdf` in the system temp + app temp dirs once per run on first
  load (app killed mid-upload). Test: `test/privacy/leftover_copies_test.dart`.
- Still open (see PENDING #27): own the invite domain (`docs/INVITE_DOMAIN.md`
  — `vitalog.app` is taken, pick another); verified App Links / Associated
  Domains to replace the `com.vitalog.app://` hand-over; bind the invite's
  wrapped key to its profile id (AAD); rotate profile key after removal.

### 2.2 Combine "You" profiles on accepting an invite ✅
- `FamilyHealthRepository.combineMembers(fromId, intoId)` (+ impl, under the
  repository lock): reports move to the shared profile **unsynced** (next
  Sync seals them with the shared key); a report whose `fileHash` is already
  in the shared profile is dropped locally; results re-judged by usual range;
  the old member's name, initials, sex, birth year and photo are kept; old
  member removed; signed in → `deleteServerMember(fromId)` (best effort).
- `HealthBloc.combineMembers` → `_SharingDone`.
- `ClaimInviteScreen._offerCombine`: after accepting as "You" with another
  "You" on the phone → `showDestructiveSheet` *Combine / Keep separate*;
  reminders are moved to the new id first. Failure never undoes the accept.
- Strings: `combineTitle`, `combineMessage`, `combineConfirm`, `combineKeep`.
- `ponytail:` limit in the impl: if the old profile was itself shared with
  someone else, moved report ids still exist there and the push under the
  shared profile fails RLS — give moved reports new ids if that happens.
- Test: `test/report_store_test.dart` "combining a profile into a shared one…".
- Docs: AGENTS.md, docs/SHARING.md (moved from "Not built yet").
